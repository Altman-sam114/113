# 本地模型完整性

`verified` 只证明受管副本符合已登记文件及摘要合同，不代表后端、许可、真机性能或发行已经验收。App 不下载模型；用户从 Files 手动选择的原件不会被导入或卸载流程修改。

## 文件合同

- Core ML compiled package 必须是目录，不能用同名普通文件冒充；GGUF 必须是非空普通文件。未知格式拒绝，路径分隔、重复必需文件名和符号链接不得取得 verified。
- 外置 tokenizer 必须是非空普通文件，且具备独立可信 SHA-256；只校验权重不能证明 tokenizer 可信。未登记 tokenizer 摘要时最多 staged，摘要不匹配的导入不能替换原代。
- GGUF 明确声明 `tokenizerIsEmbedded` 后只要求一个 GGUF，文件摘要覆盖内嵌词表。非 GGUF 不允许借此省略外置 tokenizer。
- 扫描和导入使用相同类型约束；受管根符号链接也拒绝。导入复制、类型与摘要检查全部完成后才原子替换，取消、读取失败和不匹配必须保留上一代及其他模型。

## 摘要格式

普通文件使用标准 SHA-256。目录使用 `LocalGemma.DirectorySHA256.v1` 的确定性编码，不能把它与单文件官方 SHA 混为一谈：

1. 写入 UTF-8 域 `LocalGemma.DirectorySHA256.v1` 及一个 NUL，再写 8 字节 big-endian 条目数。
2. 包含隐藏条目及空目录；拒绝符号链接和特殊文件。路径使用 `/` 分隔的相对 UTF-8 路径，并按 UTF-8 字节排序。
3. 每条依次写入类型字节（目录 `D` / 文件 `F`）、8 字节 big-endian 路径字节数及路径；文件再写其内容 SHA-256 的固定 32 字节原始 digest，目录没有内容 digest。
4. 对完整编码计算 SHA-256。文件边界、条目类型和路径长度不能互相解释；manifest 的根类型约束另外防止把整段编码做成普通文件冒充目录。

该格式与旧的未分帧目录摘要不兼容；不得将旧摘要或对整个 ZIP 的摘要直接登记为新目录摘要。真实模型与 tokenizer 的可信来源、固定版本及许可仍需分别记录，不能将“对所选文件计算一次摘要”自动等同于来源可信。

相关测试覆盖目录边界替身、隐藏项、空目录、非法根类型、tokenizer 缺摘要/篡改/空文件/目录/链接、GGUF 单文件、取消及失败保留旧代。静态检查不代替精确 SHA 的云端 XCTest，也不能证明断电或强杀耐久。
