- ComposerBar 内部是 HStack(alignment: .bottom, spacing: 10)；输入区是 TextField("问本地模型任何问题", text: $text, axis: .vertical)。

## 目标

1. 在 ComposerBar 附近新增一个无状态、可测试的输入文字排版 policy，例如 ComposerInputTextLayoutPolicy；生产 TextField 和唯一新增 XCTest 必须读取同一组契约值，不在 View 和测试中分别复制行数或 padding 数字。
2. 用公开 SwiftUI 语义 Dynamic Type 字体替代输入框的固定 .system(size: 15, weight: .semibold)。推荐使用能保持现有视觉权重的 .subheadline.weight(.semibold) 或等价公开语义字体；最终选择必须可随 Dynamic Type 放大，不能用固定字号、缩放或手工字体大小模拟。
3. 保留当前 1...4 行范围，同时允许输入框在有限行数范围内自然垂直增长。多行文本在窄 iPhone、iPad split view、Mac Catalyst 窄窗口和 Accessibility Dynamic Type 下不能被固定高度、裁剪或压缩；不要求突破既有最多 4 行上限。

5. 保持消息发送/停止行为、Command+Return、焦点生命周期、48pt action、44pt 触控目标、ComposerBarLayoutPolicy 的 18/12/320/760 宽度策略和所有现有本地边界不变。

## 生产实现约束

### 纯值 policy

可以使用等价清晰的命名，但生产 View 与测试必须读取同一 policy。建议契约如下：

~~~swift
enum ComposerInputTextLayoutPolicy {
    static let minimumLineCount = 1
    static let maximumLineCount = 4
    static let verticalPadding: CGFloat = 12

    static var semanticFont: Font {
        .subheadline.weight(.semibold)
    }

    static var usesSemanticFont: Bool {
        true
    }

    static var allowsMultiline: Bool {
        maximumLineCount > minimumLineCount
    }

    static var allowsNaturalVerticalGrowth: Bool {
        true
    }
}
~~~

- policy 只能从静态常量和输入参数生成 CGFloat、Int、Bool、公开 Font 或其他无状态值；不得读取 Environment、Dynamic Type、主题、窗口尺寸、文本状态、模型、artifact、会话、剪贴板、时间、文件系统、网络或 runtime，也不得写入状态。
- semanticFont 可以使用 .subheadline.weight(.semibold) 或与现有 15pt semibold 视觉意图等价的公开语义字体。不得在 policy、View、测试或辅助函数中保留 .system(size: 15, ...)、minimumScaleFactor、allowsTightening 或其他固定字号逃生路径。
- 生产输入框必须直接读取 policy 的语义字体、minimumLineCount...maximumLineCount 和 verticalPadding。保留 TextField(axis: .vertical)、.textFieldStyle(.plain)、主题前景色、.focused、既有辅助修饰符和 HStack(alignment: .bottom)。
- 允许使用 .fixedSize(horizontal: false, vertical: true) 或其他公开且等价的垂直增长约束，但只能让文字自然增长，不能固定高度、裁剪、负 padding、截断、缩小或改变外部 width proposal。若当前 SwiftUI TextField 已能自然增长而无需该 modifier，应保持实现最小并在报告中说明。
- lineLimit(1...4) 表示自然增长的上限，不得改成单行、无限行或以固定高度伪造四行。不要为输入框新增第二套宽度断点、动态状态或 layout cache。
- 保持输入区内部 13pt horizontal padding、icon slot、底部对齐、主题 recessed surface、17pt 圆角和 focus glow；本轮只应调整输入文字字体及必要的公开垂直增长修饰符。
- 绝不能为了让 ImageRenderer 通过而修改 send/stop action、焦点路由、外层 frame、模型状态、辅助语义或其他历史 Dynamic Type policy。若渲染发现真实布局问题，只做 v2.82 范围内最小修复并记录实际证据。
