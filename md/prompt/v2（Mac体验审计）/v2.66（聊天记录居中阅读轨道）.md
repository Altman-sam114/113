# v2.66 聊天记录居中阅读轨道

## 版本号与分配依据

- 版本号：v2.66。
- 分配依据：v2.65 最终 commit `609cde2` 对应 GitHub Actions run `30194250281` 已完成云端验收并 PASS。

## 背景

并发只读审计确认 `ChatTranscript` 当前使用整个聊天面宽度计算气泡可用宽度，内部 `LazyVStack` 没有统一最大宽度或居中约束。在 Mac Catalyst 超宽窗口中，本地模型消息靠聊天面左侧、用户消息靠右侧，而 composer 已按 760pt 居中封顶，消息与输入区视觉轴不一致。既有 520/680/600pt 气泡上限只限制单个气泡，不限制不同角色消息之间的整体跨度。

## 目标

- 新增纯值 `ChatTranscriptTrackLayoutPolicy`，锁住 18pt 水平 padding、280pt 最小内容宽度和 920pt 最大内容宽度。
- 以 `920 + 18 * 2 = 956pt` 作为阅读轨道精确封顶阈值；窄屏保持 18pt 单侧边距，超宽窗口居中限制消息跨度。
- 保持 `ScrollView` 全宽，仅将内部消息栈设为计算后的轨道宽度并居中，确保两侧滚轮、触控板和滚动命中区域不缩窄。
- `ChatBubble` 使用轨道真实宽度计算三种角色气泡，继续遵守用户/本地模型/系统消息 520/680/600pt 最大阅读宽度。
- 既有 `ChatBubbleLayoutPolicy.contentWidth` 保留为兼容转发入口，统一转发到新策略，避免形成两套宽度算法。
- 新增纯值边界与生产渲染测试，110 -> 111。

## 非目标

- 不改变消息内容、角色名称、生成占位、token 文案或聊天气泡 Dynamic Type 策略。
- 不改变 `ChatMessageAccessibilityMetadata`、`ChatTranscriptAccessibilityMetadata`、自动滚动、Reduce Motion、流式生成、会话、composer focus、导出、runtime 或 verified 门禁。
- 不限制整个 `ScrollView` 宽度，不叠加第二层 18pt 水平 padding，不把阅读轨道直接改成 composer 的 760pt 上限。
- 不下载模型权重，不接云端推理，不新增原生 macOS target。

## 实现与验证要求

1. `ChatTranscriptTrackLayoutPolicy.contentWidth(forContainerWidth:)` 对 390/620/834/900/955.99/956/1220pt 分别返回 354/584/798/864/919.99/920/920pt。
2. NaN、正负 Infinity、0 和负宽度统一回退 280pt；所有有效结果保持有限并夹在 280...920pt。
3. `ScrollView` 保持全宽；内部 `LazyVStack` 使用轨道宽度并在聊天面居中，现有 `.padding(.horizontal, 18)` 不得与策略重复计算。
4. `ChatBubble` 的 `availableWidth` 使用轨道宽度；普通字号和 Accessibility Dynamic Type 下仍分别遵守既有角色宽度与 520/680/600pt 最大阅读宽度。
5. 既有 `ChatBubbleLayoutPolicy.contentWidth` 只作兼容转发，并由测试锁住与新策略结果一致。
6. 生产 `ChatTranscript` 在 620/956/1220pt 做非空、有限尺寸 `ImageRenderer` 烟测，不使用脆弱的逐像素快照断言。
7. 只通过 GitHub Actions 执行 iOS build、Mac Catalyst build、LogicSmoke 和完整 111 项 XCTest；不运行本地 Xcode、Simulator、Mac build 或截图。
8. 同步 `AGENTS.md`、`README.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和 `update_log.md`。
