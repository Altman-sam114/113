# v2.80 Agent B 提示词：设置偏好行响应式布局

## 版本与依据

- 版本：v2.80。
- 分配依据：update_log.md 当前最新正式版本为 v2.79；v2.79 已由 commit 48d0bd2 的云端 run 32630763166 attempt 2 验收通过，继续递增一个小版本。
- 总目标：持续提升 Local Gemma 在 iPhone、iPad 和 Mac Catalyst 上的 UI 可读性、响应式表现和科技感；本轮只处理设置页偏好行的窄宽布局，不扩大到其他 workspace。

## 背景与问题

SettingsWorkspace 在 LocalGemma/ContentView.swift 约 6578 行，使用真实容器宽度控制设置页整体内容。WallpaperPreferencePanel 约 6799 行的偏好内容固定为横向 HStack：58pt 壁纸预览、标题/状态文案、Spacer，以及两个 44pt 图标动作。窄 iPad split view 或 Mac Catalyst 窄窗口下，panel 内可用内容宽度可能约 256pt，状态文案实际可用空间约 88pt；较大 Dynamic Type 下虽然允许两行，也仍被横向结构压缩，造成难读、拥挤或布局高度不足。

当前 ThemePreferencePanel 和 WallpaperPreferencePanel 已有 SettingsPreferenceTextLayoutPolicy，动作已由 SettingsIconActionLayoutPolicy 保证至少 44pt，壁纸选择和清除操作已有 WallpaperPreferenceAccessibilityMetadata。不要把已有状态边界误判成待重构对象。

## 目标

1. 新增无状态、可单测的 SettingsPreferenceRowLayoutMode / SettingsPreferenceRowLayoutPlan / SettingsPreferenceRowLayoutPolicy（名称可与现有项目风格等价调整），由调用侧传入真实 panel 内容宽度与 DynamicTypeSize。
2. 普通 Dynamic Type 只有在明确且可解释的最小内容宽度阈值达到时才使用横排；窄宽度必须使用堆叠布局。阈值应能容纳 58pt preview、文案最小可读宽度、两个 44pt action、动作间距和布局间距，不能只按外层窗口宽度猜测。
3. .xxxLarge 及以上 Accessibility Dynamic Type 始终使用 stacked；NaN、infinity、零和负宽度必须安全回退到 stacked，不得产生负尺寸或布局崩溃。
4. WallpaperPreferencePanel 使用同一组 preview、文案、actions 子树，通过 AnyLayout 在 horizontal/stacked 间切换，避免两套实现造成状态或辅助语义漂移。stacked 时仍保持预览、状态文案、选择/清除动作的清晰顺序和自然垂直增长。
5. 保留已有标题/状态 Dynamic Type 字体、SettingsPreferenceTextLayoutPolicy、主题颜色、panel style、壁纸预览、PhotosPicker、导入进度、清除禁用态和全部辅助语义。图标动作在任何布局下仍至少 44pt。

## 非目标与硬边界

- 不修改 AppState.swift、WallpaperImageProcessor、AppStorage、PhotosPicker 选择/导入 Task、主题切换、壁纸数据保存或恢复系统背景行为。
- 不改变 WallpaperPreferenceAccessibilityMetadata 的 label/value/hint/input labels/identifier、VoiceOver/Voice Control 可达性或禁用状态。
- 不改变 DeviceOptimizer、模型文件、artifact validation、runtime、verified 门禁、会话、composer focus、workspace navigation、Reduce Motion 或云端隐私边界。
- 不下载模型权重，不执行真实模型推理，不接入云端推理，不引入网络或 UIKit 状态层 workaround。
- 不用全局 scrollDisabled、透明手势阻断层、私有 API 或第二套不受测断点；不做无关 UI 重构。

## Agent B 实现步骤

1. 开始前执行 git fetch origin、确认当前为 main，并 git pull --ff-only origin main；阅读 AGENTS.md、update_log.md、md/flow/flow.md、md/flow/flowchart.md、md/test/test.md、README.md、md/prompt/README.md，以及 SettingsWorkspace、WallpaperPreferencePanel、相关 metadata 和测试。
2. 在 LocalGemma/ContentView.swift 靠近设置布局 policy 的位置新增纯值 mode/plan/policy。Plan 至少表达布局模式、真实宽度、是否允许横排或等价的明确结果；所有非法输入都需确定性回退。
3. 在 WallpaperPreferencePanel 读取 @Environment(\.dynamicTypeSize)，用 GeometryReader 或现有真实 panel 内容宽度传给 policy；不能把 GeometryReader 放到会改变 panel 外层滚动宽度的第二套根布局中。
4. 用 AnyLayout 保持同一 preview/text/actions 子树。横排保留当前 iPhone/宽 split view 的紧凑表现；stacked 时让文案和 actions 获得完整宽度，动作仍可命中且不改变操作闭包。
5. 在 LocalGemmaTests/LocalGemmaTests.swift 增加唯一 XCTest，覆盖 policy 边界、Dynamic Type、非法宽度、44pt 动作契约和真实 WallpaperPreferencePanel 渲染。不要删除、跳过或放宽已有测试，也不要把 ImageRenderer 结果伪造为尺寸断言。
6. 同步更新 AGENTS.md 当前能力摘要/边界、update_log.md、md/test/test.md、md/flow/flow.md、md/flow/flowchart.md、README.md，并保留本 prompt 文件。文档必须写实际测试命令和云端结果，不得提前伪造 run/artifact。

## 测试要求

纯值测试至少锁住：

- 256pt、320pt、354pt、760pt 等真实内容宽度边界和阈值前后行为；
- .large、.xxxLarge、.accessibility3 的 layout mode；Accessibility Dynamic Type 不得横排；
- 0、负数、CGFloat.nan、CGFloat.infinity 的确定性 stacked fallback；
- preview slot、文案区域、action row 的最小尺寸推导，两个 icon action 都不低于 44pt；
- 空壁纸、有自定义壁纸、导入中三种状态只影响既有状态/禁用契约，不影响布局 policy 的安全性。

真实生产渲染至少用公开 ImageRenderer 覆盖 WallpaperPreferencePanel：

- 宽度：256、320、354、760pt；
- 主题：light/dark；Dynamic Type：.large、.xxxLarge、.accessibility3；
- wallpaper data：空、有有效小图片；isImporting：false/true；
- 每个组合必须得到非空、有限、正尺寸；stacked 组合的高度不能比对应横排基线不合理地缩小；生产两个动作的公开 accessibility identifiers、disabled 状态和 44pt frame 契约保持可核对。

保留并回归既有设置页、壁纸处理、图标动作、辅助语义、optimizer grid、model/runtime/verified 测试。若 ImageRenderer 无法稳定观察 PhotosPicker 私有内部树，只断言生产 panel 外壳的有限正尺寸，并以纯 policy、metadata 和 button frame 契约覆盖行为，不替换真实生产 view。

## 风险

- GeometryReader 若读取外层 proxy 而非 panel 内真实内容宽度，可能在窄 split view 中错误横排；必须通过 ImageRenderer/纯 policy 边界锁住。
- AnyLayout 两个分支若复制动作闭包或 accessibility modifier，可能造成状态流/辅助语义漂移；优先共享子树或抽取只读局部 view。
- PhotosPicker 的平台内部渲染可能改变 ImageRenderer 高度；不要为测试而替换 PhotosPicker 或修改导入状态。
- .xxxLarge 及以上必须稳定 stacked，避免 Dynamic Type 改变时出现不可预测列切换。
- 不得伪造测试结果；云端 run 完成前文档写“待验证”，Agent C 验收后再补实际 run/artifact 证据。
