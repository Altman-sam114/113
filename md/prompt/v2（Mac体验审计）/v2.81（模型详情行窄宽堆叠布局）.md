## 审计背景

当前 LocalGemma/ContentView.swift 的模型详情实现边界如下，行号仅作定位，必须以最新源码为准：

- ModelDetailColumn 依次展示 ModelSummaryPanel、ModelParametersPanel、ModelPerformancePanel 和 ModelAdvicePanel，并保留 ModelDetailAccessibilityMetadata 的整体辅助语义。

- ModelParametersPanel 和 ModelPerformancePanel 通过 DetailRow(title:value:) 展示静态标题/数值；ModelAdvicePanel 通过 AdviceRow 展示 blocker、next step 和 chip strategy。

- 当前既有 testModelDetailPanelTextLayoutPolicySupportsDynamicTypeHeadings 已使用真实 ImageRenderer 渲染三类 panel，但没有独立锁住真实 DetailRow 的窄宽 layout mode、content width 到 mode 的确定性映射，且不能替代本轮新 contract。

## 本轮目标

1. 新增无状态、可单测的 ModelDetailRowLayoutPolicy，以及清晰的 ModelDetailRowLayoutMode / ModelDetailRowLayoutPlan（命名可等价调整），用真实详情 panel content width 和 DynamicTypeSize 决定 DetailRow 使用横排还是堆叠。
2. 在普通 Dynamic Type 下为窄内容宽度提供稳定 stacked fallback；在 .xxxLarge 及以上 Accessibility Dynamic Type 下，无论宽度多大都 stacked，避免大字号继续被 title/value 双列压缩。
3. 让生产 DetailRow 消费同一 policy：横排保留当前紧凑 title/value 对齐，stacked 按标题在上、数值在下的自然垂直顺序展示；两种模式共用真实文本、主题和辅助语义子树，不复制状态或动作闭包。
4. 用公开 ImageRenderer 覆盖真实 DetailRow、ModelParametersPanel、ModelPerformancePanel 和 ModelAdvicePanel 的宽度、亮暗主题和 Dynamic Type 矩阵，确保窄宽堆叠和大字号不会产生空渲染、负尺寸或高度塌缩。
5. 保留模型详情整体/行级辅助语义、panel 视觉层级、模型选择/部署、artifact 文件工作流、runtime preparation 和 verified 门禁；本轮只改善信息排版，不改变任何状态流。

## 建议的纯值 API 与数值契约

Agent B 可以使用等价清晰的命名，但生产 View 与 XCTest 必须读取同一 policy，不能在 View 内复制断点或间距数字。建议契约如下：

    enum ModelDetailRowLayoutMode: Equatable {
        case stacked
        case horizontal
    }

    struct ModelDetailRowLayoutPlan: Equatable {
        let mode: ModelDetailRowLayoutMode
        let contentWidth: CGFloat
        let allowsHorizontal: Bool
    }

    enum ModelDetailRowLayoutPolicy {
        static let minimumTitleColumnWidth: CGFloat = 84
        static let minimumValueColumnWidth: CGFloat = 264
        static let horizontalSpacing: CGFloat =
            ModelDetailRowTextLayoutPolicy.horizontalSpacing

        static var horizontalContentWidthThreshold: CGFloat {
            minimumTitleColumnWidth
                + minimumValueColumnWidth
                + horizontalSpacing
        }

        static func panelContentWidth(forPanelWidth panelWidth: CGFloat) -> CGFloat

        static func resolve(
            contentWidth: CGFloat,
            dynamicTypeSize: DynamicTypeSize
        ) -> ModelDetailRowLayoutPlan
    }

实现契约：

- 默认数值按 84pt + 264pt + 12pt = 360pt 的保守真实内容宽度阈值锁定。84pt 为标题列的可读下限，264pt 为默认本地模型详情值和 Dynamic Type `.large` 下的可读保留宽度，12pt 复用现有 title/value 间距；不得只按外层窗口宽度猜测。当前并发候选已经写入 360pt，但它必须补上这种可解释的派生契约，不能只留下 magic number。若实际实现因 SwiftUI proposal 或现有布局必须采用等价值，必须在测试、update_log.md 和 Agent B 报告中解释，仍须保留一个可复现的单一阈值，不得引入第二套断点。
- panelContentWidth(forPanelWidth:) 如实现，必须复用 WorkbenchVisualStylePolicy.panelPadding，对合法正有限 panel 外框宽度扣除两侧 14pt，并将非法、零、负数安全归一为有限的 0pt。resolve 的输入是已经得到的真实 panel content width，不是 ModelDetailColumn 的猜测宽度。
- resolve 对合法宽度只保留有限正值；NaN、Infinity、零和负数必须回退为 contentWidth = 0、mode = .stacked、allowsHorizontal = false。不得让 NaN/Infinity 流入 frame、GeometryReader、Layout 或 renderer。
- .large 在 horizontalContentWidthThreshold - 0.01 必须 stacked，在阈值处必须 horizontal；.xxxLarge、.accessibility3 以及更大的 Dynamic Type 必须 stacked，即使 content width 大于阈值。
- policy 只能读取传入的 CGFloat 与 DynamicTypeSize，返回纯值；不得读取主题、Environment、模型、artifact、会话、剪贴板、时间、文件系统、网络或 runtime，不得写入 @State / @Published / AppStorage。
- ModelDetailRowTextLayoutPolicy 继续拥有文本 line limit、line spacing、minimumRowHeight = 28 等文字契约；不要把这两个 policy 合并成一组难以单测的环境对象。现有 static 详情行不是动作控件，不要为了 44pt 目标把每一行改成 Button 或凭空增加点击行为。

## 生产 View 实现要求

- DetailRow 必须读取 dynamicTypeSize 或等价公开环境入口，并将真实 content width 与 Dynamic Type 交给 ModelDetailRowLayoutPolicy.resolve。宽度可以通过显式父级 proposal、公共 Layout、环境宽度值或等价公开 SwiftUI 机制传递。
- 优先让 DetailPanel/其内容布局传递 panelStyle 14pt padding 之后的真实 content width；不要使用 ModelDetailColumn、窗口宽度或固定 320/390pt 作为生产断点。
- 不能用 `.greatestFiniteMagnitude`、一个默认的大于阈值常量或“没有传宽度就永远横排”作为生产 fallback；既有无参数 convenience initializer 也必须通过真实父级 proposal/context 得到有限宽度，或安全 stacked。现有三类 panel 的默认生产调用必须真正经过窄宽 policy，不能只让新增测试通过显式参数绕过生产路径。
- 若使用 GeometryReader，只能作为受约束的 layout/background/overlay 测量或等价公开布局实现，不能把一个无限扩张的 GeometryReader 放进 DetailPanel 的 intrinsic-height 根节点，不能重现 v2.80 已修复的 stacked 高度塌缩。生产 panel 在每个合法矩阵组合都必须自然得到有限正高度。
- horizontal 模式保留当前 title/value 的 HStack(alignment: .firstTextBaseline)、12pt 间距、标题/数值语义字体、数值尾部对齐和已有 line limit；允许使用 policy 转发的 spacing，不得复制 12。
- stacked 模式使用同一 title/value 文本子树切换为 VStack(alignment: .leading, spacing: ...)；标题在上、数值在下，数值获得完整可用行宽并以可读的 leading 对齐；数值和标题仍使用既有 Dynamic Type 语义字体、line limit、fixedSize(horizontal: false, vertical: true) 或等价公开垂直增长约束。
- 不得用 .system(size:) 固定字号、minimumScaleFactor、allowsTightening、clipped()、固定高度、负 padding 或截断来解决窄宽问题。不要移除既有两行标题/数值契约；若必须调整 line limit，需有真实渲染证据并保持自然垂直增长。
- DetailRow 的外层继续 frame(maxWidth: .infinity, minHeight: ModelDetailRowTextLayoutPolicy.minimumRowHeight)；stacked 内容允许超过 28pt 自然增长，不能把 28pt 当成固定 height。
- AdviceRow 不是本轮新的 title/value 双列对象。它继续使用当前 icon + text 结构、16pt icon slot、9pt spacing、4 行建议限制、2pt line spacing 和自然垂直增长；三类 panel 渲染矩阵必须把它作为 ModelAdvicePanel 回归覆盖，不得改写 blocker/next step/chip strategy 顺序或语义。
- 不要复制 DetailRow 的 label/value 内容到第二套 stacked view。可以使用 AnyLayout、公开 custom Layout 或等价方案，但 horizontal/stacked 必须共享实际文本和 modifier 的语义来源，避免状态、主题和 Dynamic Type 漂移。
