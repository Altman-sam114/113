# v2.65 聊天气泡文本动态排版

## 版本号与分配依据

- 版本号：v2.65。
- 分配依据：v2.64 已完成实现 commit `c197c04`、验收记录 commit `6e1edac` 和最终 run `30192901617` 云端闭环。

## 背景

并发只读审计确认 `ChatBubble` 的角色标签、正文、token 图标和元数据仍使用固定 9/10/15pt 字号；Accessibility Dynamic Type 下，既有 40/24pt 左右 reserve 与 58%/76%/72% 角色比例还会继续压缩正文宽度。会话 chip 等相邻高频控件已经使用语义字体，聊天正文仍是明显缺口。

## 目标

- 新增纯值 `ChatBubbleTextLayoutPolicy` 与可比较布局计划。
- 角色、正文和 token 元数据改用 Dynamic Type 语义字体并允许完整垂直增长。
- 普通字号保留既有角色比例、左右对齐与最大阅读宽度。
- Accessibility Dynamic Type 下移除角色比例、40/24pt reserve 和 8pt 相邻间距，使用真实可用宽度，但继续遵守用户/本地模型/系统消息 520/680/600pt 最大阅读宽度。
- 新增纯值边界和生产 `ImageRenderer` 测试，109 -> 110。

## 非目标

- 不修改消息内容、角色名称、生成占位或 token 文案。
- 不改变 `ChatMessageAccessibilityMetadata`、`ChatTranscriptAccessibilityMetadata`、自动滚动、流式生成、会话、composer focus、导出、runtime 或 verified 门禁。
- 不同时实现聊天记录统一阅读轨道；该候选留给后续独立版本。
- 不下载模型权重，不接云端推理，不新增原生 macOS target。

## 实现与验证要求

1. 普通 Dynamic Type 保持 `ChatBubbleLayoutPolicy` 既有宽度结果。
2. Accessibility Dynamic Type 对三种消息角色使用零 reserve 和真实可用宽度，同时保留最大阅读宽度。
3. 测试覆盖 `.large`、`.xxxLarge`、`.accessibility1...5`、320/620pt、NaN、Infinity、负值和三种角色。
4. 生产 `ImageRenderer` 验证长正文与长 token 元数据在多字号下生成非空、有限尺寸图像。
5. 只通过 GitHub Actions 执行 iOS build、Mac Catalyst build、LogicSmoke 和完整 XCTest；不运行本地 Xcode、Simulator、Mac build 或截图。
6. 同步 `AGENTS.md`、`README.md`、`md/flow/flow.md`、`md/flow/flowchart.md`、`md/test/test.md` 和 `update_log.md`。

## 云端闭环要求

1. Agent B 基于最新 `origin/main` 在 `main` 提交并推送，提交中必须排除用户未提交的 `LocalGemma.xcodeproj/project.pbxproj` 签名配置。
2. 等待该 commit 对应的 GitHub Actions run 完成并下载唯一未过期 artifact；不得验收旧 run。
3. artifact 名、manifest 的 `version=v2.65`、repository、branch、commitSha、runId、runAttempt 必须与 GitHub API 精确一致。
4. static、LogicSmoke、iOS build、110 项 XCTest、Mac Catalyst build 和 run-script contract 必须 success；JUnit 必须 0 failure，三份 xcresult 必须存在且有效。
5. Agent C 独立下载并验收最新 artifact；失败时由 Agent B 在 `main` 追加修复提交，禁止回滚式覆盖。
6. Agent C PASS 后在 `update_log.md` 追加 run、commit、artifact、manifest、JUnit、日志与 xcresult 证据，单独提交推送并验收该记录提交对应的最终云端 run。
