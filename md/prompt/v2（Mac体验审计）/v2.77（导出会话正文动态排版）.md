### 体验问题

- iPad split view、iPad 宽 sheet、Mac Catalyst 窄窗口和大 Dynamic Type 下，固定 13pt 等宽字体不会随系统语义字号增长。用户需要阅读或选择较长本地 Markdown 时，正文层级和可读性低于已适配的标题、聊天气泡和设置内容。
- 当前正文没有 line spacing 的共享纯值契约，且 padding 数字直接写在 ExportSessionView 中。缺口是局部、可渲染、可回归的文字排版问题，不需要新增状态或业务逻辑。
- 导出正文是完整本地文本，不能通过 lineLimit、截断、minimumScaleFactor、allowsTightening 或固定高度来“解决”大字号；长文本必须继续滚动，文本选择必须继续可用。

## 目标

1. 新增无状态 ExportSessionBodyTextLayoutPolicy，集中定义导出正文的 content padding、line spacing 和“保留完整正文”的纯值契约。
2. ExportSessionView 的预览正文改用公开 SwiftUI 语义字体 .body.monospaced() 或等价的 Dynamic Type 等宽字体入口，并允许文字按大字号自然垂直增长。
3. 复用现有 ExportSessionLayoutPolicy 的 320pt/760pt 宽度策略；正文在 iPhone、iPad split view、iPad 宽 sheet 和 Mac Catalyst 窗口中保持稳定可读轨道，不引入第二套宽度断点。

5. 保留现有 ExportSessionTitleTextLayoutPolicy、ExportSessionActionLayoutPolicy 的标题、按钮高度、toolbar 44pt 和 Reduce Motion 行为；本轮不增加动画入口。
6. 在 .large、.xxxLarge 和至少一个 Accessibility Dynamic Type 下锁住真实 ExportSessionView 的非空生产渲染；较大文字导致正文高度增加是允许且预期的。

## 建议纯值 API

Agent B 可以使用同等清晰的命名，但生产 View 和 XCTest 必须共享同一 policy，不得在 View 内复制数字：

    enum ExportSessionBodyTextLayoutPolicy {
        static let contentPadding: CGFloat = 18

            true
        }
    }

实现约束：

1. API 必须是可重复读取的静态纯值入口，只含 CGFloat、Bool 或无状态计算属性；不得读取 Environment、主题、窗口尺寸、ExportPayload、会话、剪贴板、时间或 runtime。

4. preservesFullText 必须保持为 true。生产正文不得添加 lineLimit 或固定高度；滚动容器负责长文本可见性。
5. ExportSessionBodyTextLayoutPolicy 不得重新定义 ExportSessionLayoutPolicy 的宽度常量。正文的 frame(maxWidth: .infinity, alignment: .leading) 和父级 content width 继续复用现有布局。
