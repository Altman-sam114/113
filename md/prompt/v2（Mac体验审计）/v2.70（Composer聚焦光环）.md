## 背景与目标

`ComposerBar`（`LocalGemma/ContentView.swift` 第 5031-5139 行）当前对键盘焦点没有任何视觉反馈：

- 内场输入区（第 5044-5070 行）：`recessedSurface` 圆角 17pt 背景，描边 overlay（第 5067-5070 行）恒为 `stroke(theme.border, lineWidth: 1)`，聚焦与否完全一样。`@FocusState focusedField`（第 5033 行）与 `.focused($focusedField, equals: .input)`（第 5059 行）已存在，可直接读 `focusedField == .input` 驱动样式。
- 外壳（第 5098-5103 行）：`.padding(8)` + `.ultraThinMaterial` 圆角 22pt + 描边 `isGenerating ? theme.success.opacity(0.32) : theme.accent.opacity(0.18)`；外壳已有生成态语义描边，本轮不改外壳。
- 发送/停止圆钮（第 5072-5096 行）：填充为纯色 `.background(isGenerating ? Color.red.opacity(0.9) : theme.accent, in: Circle())`（第 5085 行），无渐变、无深度。

v2.70 用纯静态样式（零动画，天然 Reduce Motion 免疫）为 composer 增加聚焦光环与发送按钮渐变：

1. 内场聚焦反馈（只改内场描边 overlay，第 5067-5070 行）：
   - 聚焦（`focusedField == .input`）时描边改为 `theme.accent.opacity(0.55)`、lineWidth 1.5；并在该描边 `RoundedRectangle`（cornerRadius 17）上加 `.shadow(color: theme.accent.opacity(theme.isDark ? 0.35 : 0.20), radius: 10, x: 0, y: 0)` 形成柔和光环。shadow 挂在 overlay 的描边形状上而不是整个输入容器上，避免文字投影；shadow 不参与布局，不改任何 frame/padding。
   - 未聚焦保持与现状视觉等价：描边继续用 `theme.border`（注意：`theme.border` 是 `isDark ? Color.white.opacity(0.14) : Color.black.opacity(0.10)`，第 59 行，与 accent 无关，**不存在** "accent.opacity(x) 等价表达"——所以未聚焦分支必须原样保留 `theme.border` 颜色，不得换成 accent 低透明近似）、lineWidth 1、glow opacity 0（即无 shadow 效果）。
2. 发送/停止圆钮渐变（只改第 5085 行的填充表达）：
   - 发送态填充改 `LinearGradient(colors: [theme.accent.opacity(1.0), theme.accent.opacity(0.78)], startPoint: .topLeading, endPoint: .bottomTrailing)`，填入同一个 `Circle()` shape。
   - 停止态保持红色语义，同构渐变 `[Color.red.opacity(0.9), Color.red.opacity(0.7)]`，同端点。
   - 可用（`!isSendDisabled`，即有文字可发送或生成中可停止）时在按钮上加 `.shadow(color: <当前基色>.opacity(theme.isDark ? 0.45 : 0.28), radius: 8, x: 0, y: 0)`；基色随状态取 `theme.accent`（发送）或 `Color.red`（停止）。禁用时 glow opacity 为 0。第 5091 行既有 `.opacity(isSendDisabled ? 0.55 : 1)` 保留不动。
3. 焦点变化时属性直变，不加任何 `withAnimation`、`animation(_:value:)`、transition 或 `.task` 动画驱动——本轮零动画，不新增动画入口，不触碰 `AppMotionEffect` / `AppMotionAccessibilityPolicy`。

新增纯值 `ComposerFocusGlowStylePolicy`（enum + static 常量/函数，风格对齐 `GenerationIndicatorStylePolicy`、`SessionChipVisualStylePolicy` 等既有 policy；放在 `ComposerBar` 附近或既有 policy 聚集区均可）：

- `focusedBorderOpacity: Double = 0.55`（聚焦描边的 accent 透明度）。
- `usesAccentBorder(isFocused: Bool) -> Bool`：true/false，视图据此在 `theme.accent.opacity(focusedBorderOpacity)` 与 `theme.border` 之间选择——因为未聚焦色不能用 accent 表达（见上），policy 用布尔分支而不是统一 opacity 函数。
- `lineWidth(isFocused: Bool) -> CGFloat`：1.5 / 1。
- `glowRadius: CGFloat = 10`。
- `glowOpacity(isFocused: Bool, isDark: Bool) -> Double`：未聚焦一律 0；聚焦时暗 0.35 / 亮 0.20。
- `sendGlowRadius: CGFloat = 8`。
- `sendGlowOpacity(isEnabled: Bool, isDark: Bool) -> Double`：禁用一律 0；可用时暗 0.45 / 亮 0.28。
- `gradientTopOpacity: Double = 1.0`、`gradientBottomOpacity: Double = 0.78`（发送渐变端点）；停止态端点 0.9 / 0.7 也提炼为常量（如 `stopGradientTopOpacity` / `stopGradientBottomOpacity`），停止顶端 0.9 必须与现状纯色 `red.opacity(0.9)` 一致，保证停止态视觉延续。

具体 API 命名可微调，但必须保持 enum + static 纯值、无状态、可被 XCTest 直接断言；`ComposerBar` 视图从策略读取全部常量，不散落魔法数字。

## 风险与禁止项

- `theme.border` 未聚焦分支若被误改为 accent 低透明近似，亮/暗主题下会与全应用其余 hairline 不一致——未聚焦必须原样 `theme.border`。
- shadow 若挂在整个输入容器而非描边 overlay 形状上，会给 TextField 文字带投影；必须挂在 overlay 的 `RoundedRectangle` 描边上。
- 停止态渐变顶端若偏离 0.9 会削弱既有红色语义延续性；端点常量必须与现状对齐。
- 渲染矩阵若尝试注入聚焦态（反射、私有 API、宿主层级探查）即违反禁令；聚焦契约只用纯值断言。
- 禁止下载模型权重、禁止云端推理、禁止绕过 artifact verified 门禁、禁止伪造测试结果、禁止验收旧 run/旧 artifact、禁止编辑用户的 `project.pbxproj`、禁止给 `AppMotionEffect` 加 case、禁止改任何 `*AccessibilityMetadata` 文案、禁止新增 `withAnimation` 或其他动画入口、禁止删改 Agent C 并行提交的 v2.69 验收记录。
