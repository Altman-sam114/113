# v2.72 单条消息复制动作

## 版本依据

- 基线：`main` / `origin/main` commit `c1b1421`。Agent B 开工前必须执行 `git fetch origin`、`git switch main`、`git pull --ff-only origin main`，并确认 `HEAD == origin/main`；实现与验收以拉取后的最新 `origin/main` 为准，不得基于陈旧快照。
- v2.71 已完成共享 panel 内高光与 contact/ambient 分层阴影；本轮总目标 X 继续提升 iPhone、iPad 与 Mac Catalyst 的聊天工作流效率，只为 `ChatBubble` 增加单条消息复制动作与持久 checkmark 反馈。
- 工作区已有用户改动 `LocalGemma.xcodeproj/project.pbxproj`。严禁编辑、格式化、暂存、覆盖、提交或回滚；每次暂存与提交必须显式排除该文件。

## 背景与目标

当前会话导出弹层支持复制全文，但聊天气泡没有直接复制单条消息的入口。Mac/iPad 用户摘取某一条回复时只能选择文本或导出整个会话，操作成本偏高。`ChatBubble` 当前又将整个气泡设为 `children: .ignore`，如果直接把按钮塞进现有层级，VoiceOver 将无法访问该动作。

v2.72 只完成以下闭环：

1. 用户、本地模型与系统角色的非空消息均显示单条复制按钮。
2. 点击后把原始 `message.text` 原样写入系统剪贴板，不 trim、不重排、不丢失首尾空白或换行。
3. eligibility 同时使用 trim 后是否非空和显式生成状态判断；空字符串、纯空白以及整个流式生成期间的最新 assistant 消息不可复制。
4. 成功后图标从 `doc.on.doc` 切换为 `checkmark`，反馈在该 `ChatBubble` 身份存续期间保持，不加定时器、不自动复位。
5. 消息摘要与复制动作拆成两个独立可达的辅助技术元素；复制按钮有独立 metadata、Voice Control 输入标签和稳定 identifier。
6. 按钮命中目标至少 `44x44pt`，复用既有 `.copyConfirmation` Reduce Motion 动画策略，不新增 motion case。

本轮不显示消息时间。虽然 `ChatMessage.timestamp` 已存在，但 assistant 的值代表生成开始时间而非完成时间；时间格式、时区、语义和窄屏排版留给独立版本处理。

## 纯策略边界

新增一个职责单一的纯 policy（命名可按项目风格微调，例如 `ChatMessageCopyPolicy`），生产视图不得散落 eligibility、payload 或尺寸魔法值：

- `minimumTouchTarget: CGFloat = 44`。
- `actionButtonSize: CGFloat = 44`。
- `canCopy(_:)` 只用 `trimmingCharacters(in: .whitespacesAndNewlines)` 判断消息正文非空。
- `payload(for:)` 返回未经修改的原始消息正文；禁止返回 trimmed 字符串。
- 空字符串、纯空白字符串、生成占位均不可触发剪贴板写入。
- policy 不直接访问 `UIPasteboard`，保持可确定测试。

复制按钮的系统剪贴板写入只存在于生产 action 中，沿用项目现有 `UIPasteboard.general.string` 模式。不得修改 `ChatMessage`、`InferenceEngine`、流式生成、导出 payload 或会话状态模型。

## 交互与视觉要求

- 在 `ChatBubble` 的 token/元数据区域加入低强调图标按钮，默认使用 SF Symbol `doc.on.doc`，成功后使用 `checkmark`；不得手绘 SVG。
- 按钮使用原生 `Button` 与 `.buttonStyle(.plain)`，保持至少 `44x44pt` 稳定尺寸，并提供 `.help("复制消息")` 或等价简洁帮助文本。
- `@State private var didCopy = false` 可由每个气泡本地持有。第一次成功后持续显示 checkmark，直至该气泡身份离开视图；不要引入 `Task.sleep`、Timer、自动复位、全局 copied-message ID 或新的状态层。
- 图标切换复用 `AppMotionAccessibilityPolicy.animation(for: .copyConfirmation, reduceMotion:)` 或项目现有等价入口。普通模式与 Reduce Motion 参数保持原策略；不得新增 `AppMotionEffect` case。
- 复制动作不缩放、不移动气泡、不改变 bubble alignment、最大阅读宽度、聊天轨道、自动滚动、composer 布局或消息顺序。
- Dynamic Type 下按钮不得挤压正文或 token 文本；允许元数据行自然换行或调整为稳定布局，但不得降低 44pt 命中目标。

## 辅助语义

当前整个 `ChatBubble` 使用 `.accessibilityElement(children: .ignore)`。本轮必须重组为两个同级可达元素：

1. **消息摘要元素**：将既有 `ChatMessageAccessibilityMetadata` label/value/hint/input labels/identifier 下移到只读内容容器；该容器继续使用 `children: .ignore`，保留一次完整消息摘要朗读及原稳定 identifier。
2. **复制动作元素**：复制按钮作为摘要容器同级元素，外层不得再用 `children: .ignore` 吞掉按钮；必要时只使用 `children: .contain`。

新增独立 `ChatMessageCopyAccessibilityMetadata` 或等价纯 metadata policy，至少提供：

- label：复制前为“复制消息”，成功后可明确“消息已复制”。
- value：明确“可复制 / 已复制 / 生成中不可复制”状态。
- hint：说明只把该条本地消息写入系统剪贴板，不发送到云端服务，不下载权重、不启动真实 runtime、不绕过 verified 门禁。
- Voice Control 输入标签：保持稳定，至少包含“复制消息”；成功后不得因视觉 checkmark 破坏原语音命令。
- identifier：基于消息稳定 ID 生成独立动作 identifier，不能复用消息摘要 identifier。

生成中的空文本占位必须保持既有 `ChatMessageAccessibilityMetadata` 的生成中朗读与 `GenerationIndicatorStylePolicy` 动效；流式正文出现后，最新 assistant 消息的复制按钮仍保持禁用，直到生成结束。不得造成摘要与按钮重复朗读整段消息正文。

## 实现要求

- 在 `LocalGemma/ContentView.swift` 中新增纯复制 policy、独立复制动作 accessibility metadata，并把 `InferenceEngine.isGenerating` 经 `ChatTranscript` 传给最新 assistant `ChatBubble`。
- `ChatBubble` 只在 copy eligibility 为 true 时执行 `UIPasteboard.general.string = policy.payload(text:)`；成功写入后再将 `didCopy` 设为 true。
- payload 必须逐字符等于原始 `message.text`，包括换行、Unicode、首尾空格和首尾换行。trim 只用于 eligibility。
- 生成占位不得写剪贴板，且不得因为 disabled action 破坏既有三点 pulse、Reduce Motion 静态梯度或生成中辅助文案。
- 保持每个气泡的本地反馈状态，不把复制状态写入 `ChatMessage`、`InferenceEngine`、`AppStorage` 或全局单例。
- 使用公开 SwiftUI API 与既有主题、字体、animation policy；不引入第三方依赖。

## 测试要求

在 `LocalGemmaTests/LocalGemmaTests.swift` 新增 1 个独立 XCTest，测试函数总数从 116 增至 117，命名为 `testChatMessageCopyActionPolicyPreservesLocalPayloadAndAccessibility`。既有 116 项测试必须全部保留，不得通过删除、合并或重命名旧测试凑数。

新测试必须覆盖：

- user、assistant、system 的非空正文均 eligible。
- `""`、空格、tab、换行及混合纯空白均不 eligible，覆盖 assistant 生成占位。
- payload 与输入逐字符相等，至少覆盖首尾空格、多行文本、Unicode 与首尾换行；明确证明 trim 判空不会 trim payload。
- 触控目标宽高均精确为 44 或至少为 44。
- copy metadata 覆盖 eligible/已复制/生成中不可复制状态；label、value、hint、稳定 Voice Control 输入标签和独立 identifier 正确。
- 消息摘要 identifier 保持既有值，复制动作 identifier 与摘要不同且基于消息 ID 稳定。
- `.large`、`.xxxLarge`、`.accessibility3` / `.accessibility5` 下正文、token 元数据与复制动作生产渲染可成立。
- 使用 `ImageRenderer` 渲染真实 `ChatBubble`，覆盖可复制 assistant 与生成占位、亮/暗主题、`.large`/`.xxxLarge`/`.accessibility3`，以及 280/680pt 窄/宽代表宽度；复制后的纯状态由 metadata 断言锁住，避免为私有 `@State` 注入测试后门。
- 渲染只断言 `uiImage` 非 nil、请求尺寸成立、高度大于 0 且在合理上限内；禁止断言具体像素颜色、alpha、checkmark 像素或 SwiftUI/UIKit 私有层级。
- 复用既有 `.copyConfirmation` motion policy 测试契约；确认没有新增 `AppMotionEffect` case，Reduce Motion 仍保留既有 0.12 秒局部反馈。

测试不得直接读写或断言 `UIPasteboard.general`。全局剪贴板断言会污染并发测试且不稳定；XCTest 只验证纯 eligibility/payload/metadata policy，生产 action 路径由源码审查、生产视图渲染和云端 build/test 共同覆盖。

## 风险与禁止项

- 外层继续使用 `children: .ignore` 会吞掉复制按钮；必须把摘要 metadata 下移并让摘要与动作成为两个可达元素。
- trim 后字符串写入剪贴板会破坏原始内容；trim 仅用于 eligibility，payload 必须原样返回。
- 直接 XCTest 系统剪贴板会污染并发运行；禁止读取、写入或断言 `UIPasteboard.general`。
- 自动复位 checkmark 会引入异步时序和额外状态；本轮反馈必须在气泡身份存续期间持久。
- 空文本生成占位不得复制，也不得破坏生成 indicator、生成中朗读或流式更新。
- 禁止添加时间、消息菜单或其他动作，禁止像素/alpha、私有层级与 iOS 18-only 测试 oracle。
- 禁止改变消息状态、气泡宽度、聊天轨道、自动滚动、composer、会话、辅助语义摘要内容、动画 case、runtime 或 verified 门禁。
- 禁止本地 Xcode build/test/Simulator/Catalyst，禁止伪造测试结果，禁止验收旧 run/artifact，禁止下载模型权重或接入云端推理，禁止编辑或提交用户的 `project.pbxproj`。
