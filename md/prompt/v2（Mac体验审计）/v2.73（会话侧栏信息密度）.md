## 背景

Curie 的只读审计确认，Mac Catalyst 与 iPad 宽屏进入竖向会话侧栏后，`SessionChip` 目前只有会话标题、选择入口和删除入口。`SessionSidebarLayoutPolicy` 将侧栏限制在 240...310pt，但行内仍有较多空白，多个会话只能靠标题区分，用户无法快速判断会话规模和最近讨论内容。

当前实现边界：

- `ChatSession` 在 `LocalGemma/AppState.swift` 中包含 `id`、`title`、按数组顺序排列的 `messages`、`createdAt` 和 `updatedAt`；`ChatMessage` 包含 `text`、`timestamp` 和其他消息字段。
- `SessionBarLayout` 只有 `.horizontal` 与 `.vertical`；`SessionBar` 仍按传入 `sessions` 数组顺序 `ForEach`，不得在本轮重新排序或改变滚动结构。
- `SessionChip` 在 `LocalGemma/ContentView.swift` 中负责标题、选择 Button、删除 Button、现有 44pt 触控目标、`SessionChipActionAccessibilityMetadata` 和 `SessionChipVisualStylePolicy`。
- 既有 `SessionSidebarLayoutPolicy`、`SessionChipTextLayoutPolicy`、`SessionChipActionLayoutPolicy`、`SessionChipVisualStylePolicy` 和 `SessionChipActionAccessibilityMetadata` 已经锁住侧栏宽度、Dynamic Type 标题、选中/删除动作、视觉层级与辅助语义。本轮只增加竖向行的本地派生信息。

## 目标

1. 新增纯值 `SessionChipSidebarMetadataPolicy`，为竖向会话行提供稳定、可测试的消息数量和最近消息摘要，提升 240...310pt Mac/iPad 会话侧栏的信息扫描效率。
2. `SessionChipSidebarMetadataPolicy` 的纯值输入必须只有一个 `ChatSession` 和一个 `SessionBarLayout`。策略不得读取环境、窗口宽度、主题、Dynamic Type、选中状态、当前时间、系统时钟、剪贴板、网络或其他全局状态。
3. `.vertical` 的派生结果必须同时包含：
   - 消息数显示值，基于 `session.messages.count`；
   - 最近非空消息摘要，基于 `messages` 数组顺序末端的最后一条正文非空消息。
4. 最近消息的“最近”只表示数组顺序，不表示时间顺序：从数组尾部向前找最后一条归一化后非空的 `message.text`，不得按 `ChatMessage.timestamp`、`ChatSession.updatedAt` 或 `createdAt` 排序、比较或显示。
5. 摘要归一化必须去掉首尾空白和换行，并把正文内部连续的空白、Tab、回车/换行等 whitespace 归一化为单个空格，使多行消息在侧栏中成为紧凑、可读的单行/多行摘要；不得改变原始 `ChatSession` 或其中任何 `ChatMessage.text`。
6. 如果整个消息数组没有归一化后非空的正文，摘要显示值必须回退为消息数显示值，而不是空字符串、时间戳或“最近消息不存在”的额外状态文案。`messages.count == 0` 也必须稳定地产生可渲染的消息数/摘要回退值。
7. `.horizontal` 必须保持现有紧凑会话胶囊不变：策略返回隐藏/无侧栏 metadata 的纯值结果，`SessionChip` 不渲染消息数或摘要，不改变现有标题、宽度、胶囊视觉、滚动或动作。
8. `SessionChip` 只能渲染 `SessionChipSidebarMetadataPolicy` 产生的派生值；不得在 View 内自行遍历、过滤、排序、读取时间戳、拼接摘要或修改消息。竖向 metadata 应放在既有选择内容的视觉层级内，不能新增独立选择/删除动作或额外状态。

建议的纯值形状可以是 `SessionChipSidebarMetadataPlan: Equatable` 加上 `resolve(session:layout:)`，或同等清晰的项目内命名；无论具体命名如何，生产 View 和 XCTest 都必须能明确区分 `.vertical` 可见结果与 `.horizontal` 不显示结果，并让 message count 与 summary 成为策略输出，而不是 View 逻辑。

- 保留当前会话选择、删除、默认空白当前会话不可删除的原因、active selected trait、会话栏新建/导出动作和会话 command menu。

- 不改变 `SessionSidebarLayoutPolicy` 的 240...310pt 宽度、`ChatWorkspacePaneLayoutPolicy` 的 860pt/620pt 边界、聊天记录 920pt 阅读轨道、短会话纵向定位、自动滚动或 composer 布局。

- 只展示本地会话已有数据，不下载 Gemma 或其他模型权重，不接入云端推理，不把 prompt、上下文或会话发送到外部服务，不新增原生 macOS target，不引入第三方依赖。

## 实现要求

1. 在 `LocalGemma/ContentView.swift` 增加 `SessionChipSidebarMetadataPolicy` 及必要的 `Equatable` 纯值计划类型；不得把新策略放进 `InferenceEngine`、`ModelCatalog` 或会话状态模型。
2. 策略内部按 `session.messages` 的数组顺序派生：消息计数使用原数组的 `count`；摘要使用从数组末端开始寻找的最后一个归一化非空正文。不要用 `sorted`、时间比较、`Date()`、`timestamp`、`createdAt` 或 `updatedAt`。
3. 归一化逻辑必须只作用于用于展示的局部 `String`，例如先判断 whitespace 归一化结果是否为空，再将连续 whitespace/newline 合并为单个空格；禁止写回 `session.messages`、`message.text` 或任何共享状态。
4. 在 `SessionChip` 中只新增 `.vertical` metadata 的渲染分支。标题和既有 action 的层级、回调、`isActive`、`canDelete`、accessibility 修饰符和 identifier 继续复用现有实现；`.horizontal` 分支保持标题-only 胶囊表现。
5. 竖向 metadata 应优先使用 `.caption` / `.caption2` 等语义字体，允许摘要自然换行并给出稳定的合理行数/布局；不要通过固定字号或缩放压缩解决 240pt、310pt 和 `.accessibility3` 下的空间问题。
6. 不为摘要增加 `@State`、`@Published`、`AppStorage`、缓存、异步任务、Timer、网络请求或新的排序/持久化层。窗口改变、Dynamic Type 改变和会话更新时由现有值刷新即可。
7. 不新增 Xcode 工程文件；所有 Swift 改动继续落在现有 target 已包含的 `ContentView.swift` 与 `LocalGemmaTests.swift` 中。

## 测试要求

在 `LocalGemmaTests/LocalGemmaTests.swift` 新增且只新增一个独立 XCTest：

```text
testSessionChipSidebarMetadataPolicyKeepsVerticalRowsScannable
```

既有 117 个测试必须全部保留，不得删除、合并、重命名或通过减少旧测试凑数；本轮完整 XCTest 总数必须从 117 增加到 **118**。

该测试必须覆盖：

- 空消息会话：`messages == []`，消息数为 0，摘要回退为同一个消息数显示值，结果可渲染且不为空。
- 空白尾消息：数组中有一条有效正文，最后一条消息只有空格、Tab、换行或混合 whitespace；必须跳过空白尾消息，选择数组中前一条有效正文，而不是返回空摘要。
- 多行尾消息：数组末尾是一条包含首尾空格和多行换行的非空正文；断言摘要去除首尾空白、把内部换行/连续 whitespace 归一化为单个空格，并保留可读的正文顺序。
- 数组顺序而非时间：构造 `timestamp` 与数组顺序相反的消息，断言摘要仍选择数组尾部向前的最后一条非空消息；测试不应依赖时间戳作为选择依据。
- `.vertical` 与 `.horizontal`：竖向结果包含 message count/summary 且可见；横向结果明确不显示侧栏 metadata，既有横向 title-only 行为仍可用。
- 不变性：在策略调用前保存完整 `ChatSession`，调用后断言原始 session、原始 `messages`、原始正文空白/换行和消息顺序完全不变；不能用 `inout` 或写回修复字符串。
- 不新增排序/状态：策略结果仅由同一 `ChatSession` 与 `SessionBarLayout` 决定，测试不要创建全局状态、持久化或网络依赖。
- 生产 `ImageRenderer`：必须渲染真实 `SessionChip`，至少覆盖 240pt 与 310pt 宽度、亮/暗主题、`.large` 与 `.accessibility3`，并覆盖选中与未选中组合；竖向行必须使用包含消息数和多行摘要的真实 session，另可用代表性横向 case 证明横向未注入 metadata。
- 对每个生产渲染只断言 `uiImage` 非 nil、请求宽度误差在 1pt 内、高度大于 0 且低于合理上限；不得做具体像素、颜色/alpha、私有 SwiftUI/UIKit 宿主层级、滚动视图层级或截图快照断言。

推荐生产渲染矩阵为 `width in [240, 310]`、`theme in [.light, .dark]`、`dynamicTypeSize in [.large, .accessibility3]`、`isActive in [true, false]`，并给 ImageRenderer 环境设置 `appTheme`、对应 `colorScheme`、`dynamicTypeSize`，`scale = 1`。测试 metadata 的精确字符串时，固定断言 count、归一化摘要、空摘要 fallback 和 horizontal hidden；不要通过访问 View 私有状态或注入测试后门证明行为。
