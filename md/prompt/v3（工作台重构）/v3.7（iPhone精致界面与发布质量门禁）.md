# v3.7 / iPhone 精致界面与发布质量门禁

日期：2026-10-28（Asia/Taipei）。Agent A 设计提示词；版本接续 `update_log.md` 的 v3.6。用户最新明确要求多 Agent 并行加速，覆盖旧版文档中的单 Agent 限制；不覆盖云端编译、数据安全与完整结果包验收规则。

## 1. 背景、依据与目标

设计起点为 `main` / `origin/main` 的 `3adaef7`。此处只确认源码身份，不预先认定 v3.6 云端或视觉验收通过。入口已存在四处未提交的 OCR/诊断修复，以及六份未跟踪历史 prompt；须保留原内容，由集成负责人核对归属和提交范围，不覆盖、不顺手提交历史 prompt。

架构依据是 `md/flow/flow.md`、`ContentView.swift` 的稳定根/四页 shell、`CompactWorkbench.swift` 的手机呈现、`ChatWorkspace.swift` 的会话与同步 focus 路由，以及四个副页文件。只读参考 `aitrans/AITRANS/Views/AppTheme.swift` 的集中 token、16/20/24pt 节奏、中性表面和小面积功能色，参考 `ContentView.swift` 的手机四入口；不修改 AITRANS，不移植它的业务、模型、分支或本机构建制度。

本轮目标是从“把桌面面板缩小”变成真正的掌上产品：信息少一层、主要操作近一步、内容比仪表板更重要。必须有实际结构和视觉改动，不能只换标题或增加装饰。iPhone 是主验收面，iPad/Catalyst 只做兼容回归。

设计方向：**安静的掌上工作台**。保留青绿品牌色、浅瓷白/深墨中性体系；以清晰的字重、留白、柔和表面和小面积精密标记体现科技感，不堆霓虹、彩虹卡片、英文工程标签或持续动画。原生语义字体优先，禁止用固定小字号、缩放文字或裁剪消除溢出。

### 可观察的交付目标

- 聊天首屏只突出当前模型、主要会话工具、短欢迎语/真实聊天内容与输入区；避免两层同等权重工具栏、重复模拟说明和占高的大装饰。
- 模型页首要问题是“当前选了什么、文件是什么状态、如何导入”；部署预览与高级参数降为次级，不把模拟状态暗示成真实推理。
- 模板页一眼可读用途，点击主区域填入，独立发送操作仍可辨认与可达；不要求先读长 prompt。
- 设置页像清晰的偏好列表，而不是层层套卡的性能仪表板；设备预算仍折叠且明确非实测。
- 320pt 小屏与较大 Dynamic Type 下没有横向溢出、主要动作截断、底栏遮挡输入或自然高度被固定容器吞掉。

## 2. 非目标与不可破坏边界

- 不改 `AppState.swift` 的模型、artifact、会话或 runtime 业务行为；不下载权重，不接入云推理，不改变默认 `SimulatedGemmaRuntime`，不把 `RealGemmaRuntimePlaceholder` 当作已实现。
- 不绕过 missing/staged/verified 门禁，不把 `manual-import-required` 视为可运行权重；部署、artifact 和生成状态不能混为一谈。
- 根布局仍只复用 `WorkspaceRootLayoutPolicy`；唯一 `WorkspacePagesShell` 的四槽同序身份、隐藏页禁用命中/控件/辅助访问不变，不恢复分页 TabView、透明手势遮罩或全局 scrollDisabled。
- composer 保留同一输入、1...4 行、48pt 发送/停止、Command+Return、同步 request/active 生命周期；离开聊天同步释放焦点，sheet 关闭后只在活动聊天请求焦点，不添加延时任务抢焦点。
- 保留会话选择、删除禁用原因、新建、导出、原消息/seed/UUID/顺序/完整导出；只改可见层级，不改内容或伪造聊天。
- 保留所有 44pt 动作、Dynamic Type、VoiceOver/Voice Control identifier 和真实语义；不会因精简视觉删除状态信息或把所有控件合并成不可单独访问的节点。
- 不新增网络字体、远程图片、动画依赖或 iOS 17 不支持的 API；不为截图添加生产测试文案。
- 真实 runtime、真机完整辅助技术、Mac GUI/pointer、签名与商店分发仍是独立发布门禁。当前 asset 未见 AppIcon 目录及工程 AppIcon 配置，须作为明确发布缺口核对，不以 UI 回归通过代替。

## 4. 实施方案

### 4.1 手机 chrome、聊天与输入

1. compact 根 chrome 采用零高占位，仍保留根同序两个节点与唯一四页 shell。聊天在自己的页面内使用单行集成头部：模型摘要、历史、新建和更多；主题/导出进入更多菜单。非聊天页不再重复全局模型栏。模型/模拟状态在聊天保留一处诚实标识，主题在设置仍直达；大字 `.xxxLarge` 及以上可把同一头部工具布局堆叠。禁止只靠无说明长按暴露动作。
2. `ChatWorkspace` 保留既有 history/export focus 状态与 sheet dismiss gate；模型摘要由聊天局部 sheet 管理，抽出 `CompactModelSummarySheet` 复用旧 `HeaderView` 摘要内容。摘要只展示传入的模型/状态/准备度，管理模型仍通过原 `selectedTab` 路由。禁止在新 sheet 内凭 availability 重新推导 deployment 或 runtime。
3. 手机公共 `SectionHeader` 只显示页面主标题，不显示英文 eyebrow 与重复 subtitle；大屏现有 Header 文本策略保留。状态解释放到本来已有的摘要或详情，不复制到每张卡片。
4. 欢迎区静态标记由 116pt 缩至约 76pt，移除重复大轨道；控制 320pt 首屏装饰占比，保持简洁短标题和两项真实 starter。starter 只填入完整 prompt 并聚焦，欢迎与 transcript 仍互斥，不能改 seed 或导出。
5. 输入与底部导航做成完整的视觉底座，使用现有 surface/accent token；原同步 editing 回调控制底栏显隐，不通过条件重建四页或 TextField。键盘“完成”和交互式收键盘保持。
6. 消息优先可读正文，角色/复制等信息清楚但低噪声。非空消息复制、空占位 active/cancelled、生成中按钮、短对话底部定位、跟随最新和 Reduce Motion 行为完整回归。
7. 装饰只挂在背景、禁用命中并从辅助树隐藏；任何新增透明效果须服从 Reduce Transparency / increased contrast 退化，不新增无限动画。

### 4.2 模型页

1. 手机 selector 去掉内外双层底板与重复规格行；一个模型身份区域展示名称、必要规格和选择入口，保留原 Picker 状态流。
2. install、artifact、deployment 三类 badge 的独立辅助契约保留，不能为了只剩一个漂亮状态点而合并错误语义。视觉可更紧凑，长文本/大字自然换行。
3. 文件主 CTA 是“导入模型文件”，扫描为次操作，暂存/卸载仍在更多菜单；卸载必须走原确认，取消无副作用。避免文件状态同时在多处重复大段展示。
4. 模拟部署控件改为较轻的次级状态/动作行，仍直说“预览”或“模拟”，不可显示伪速度或声称模型在真实推理。按钮自然高度，不加 Spacer 拉伸。
5. “参数与运行计划”继续渐进披露，完整 validation/report 和独立详情语义仍可达；所有 model-specific 动作始终绑定当前对应模型。

### 4.3 模板页

1. 手机卡片改为紧凑工具条目：图标、标题、短用途组成可点击填入主区域；原完整 prompt 不在首屏长篇展示，也不改写实际 payload。
2. 独立发送入口维持至少 44pt，清楚区分“填入”和“直接发送”；两个按钮是同级，不嵌套，不把整卡 onTapGesture 叠到发送按钮外层。
3. `isGenerating` 对填入与发送都生效，沿用 action metadata、identifier、Voice Control 输入标签及原 `openChat` focus reason。
4. 分类保持真实换行布局和 44pt，不用仅水平滑动来隐藏后面的分类，不影响已选筛选局部状态或大屏原网格。

### 4.4 设置页

1. 精简重复分组标题和卡内套卡，外观与背景、运行策略有清楚分区；以行分隔、适量留白和自然高度替代一项一张大面板。
2. `SettingsSectionsShell` 的 preferences/runtime 两节点同序身份不变。`SettingsWorkspace` 继续持有 PhotosPicker、导入中与错误状态；不把状态移动到会随布局替换的子树。
3. 四项运行开关顺序、44pt、辅助语义、optimizer 状态保持；视觉短标题可以保留中文映射，不能改变底层开关名或行为。
4. 设备/性能预算保留显式入口与“模拟数据，非实测性能”说明；不因为“少废话”隐藏真实能力边界。
5. 保持 wallpaper 预览/导入/清除禁用和本地压缩路径；大字不以硬高度压缩图片或动作，不改宽屏 882pt 内容阈值和真实列宽策略。

## 8. 风险与停止边界

OCR 的中文准确性、紧凑 UI 的真实自然高度、焦点宿主时序、公共文件并行冲突和旧状态契约是本轮主要风险。通过 owner 制、真实云端产物、自然高度与严格 identity/focus 测试控制，不能削弱门槛换速度。

删除默认 `trash <path>`；不删除用户/并行 Agent 修改，不下载历史大包/权重，不上传 prompt/会话，不引入秘密或证书。遇到无法判断归属的同文件冲突立即报告 root。需要账号/权限/密钥/付费或人工决策时明确阻塞；连续同因失败按项目 Agent X 停止规则处理，不无条件无限循环。

本提示词是设计和验收要求，不是测试结果；Agent A 未运行本地 Swift 或云端构建。
