## 4. 最小公共接口建议

接口由 X 在两名实现者和测试负责人之间先确认一次；名称可调整，但一经确认及时告知，测试不得猜接口。优先在现有文件内定义，避免新增 Xcode source 注册负担。

### 主题 owner：WorkbenchTheme.swift

- `WorkbenchActionRole`：`primary / secondary / destructive`；`WorkbenchActionPalette` 提供 `foreground / fill / border / iconSurface`，均为纯颜色值；`AppThemePalette.actionPalette(for:)` 是生产唯一映射入口。
- 同一 primary 的大部署控件宜低饱和 wash，44pt 发送动作宜实心 accent。可在 palette 内提供 `prominentFill / prominentForeground` 配对，让发送消费 prominent，避免所有 primary 被迫同一面积填色；不要另外加业务状态或多套 UI 工厂。
- `AppThemePalette.categoryTint(for:)` 直接映射现有六分类到 theme-aware 小面积颜色，不修改 `PromptTemplateCategory`；所有 apply/send 使用共享动作 palette，与分类色解耦。
- 背景只需少量静态 grid spacing/opacity 与 `showsGrid(reduceTransparency:increasedContrast:)` 纯值判断；Canvas/Path guard 非有限/非正尺寸，装饰不命中、辅助隐藏，不抢正文对比。Reduce Transparency 或 increased contrast 时取消/简化网格和光晕；保留原壁纸输入与主题遮罩逻辑。
- 不迁移未消费的 token，不改共享 panel 几何。disabled 使用原 `.disabled/.opacity` 状态流；不得只降低颜色却重新启用动作。普通正文目标对比 4.5:1，大字/必要图形目标 3:1，未测量不写成已满足。

### Shell owner：WorkbenchComponents.swift / ChatWorkspace.swift

- `ChatContentPresentation`：`welcome / transcript`；`WorkbenchPresentationPolicy.chatPresentation(messages:isGenerating:hasStarter:)` 返回单一决定。真值为 `hasStarter && !isGenerating && 无 user` 才 welcome；原 `showsWelcome` 可保留兼容，不制造两个不同判断。
- welcome 使用独立顶部定位与真实可见内容辅助摘要，隐藏 seed 不出现在可达树，也不 scrollTo 隐藏消息；transcript 恢复原 metadata、message ID 和自动滚动。无 starter 的独立 ChatTranscript 保持旧 transcript 行为。停止占位仍由原 policy 决定，不被 welcome 分支吞掉真实会话。
- 紧凑会话区 plan 只读 `SessionBarLayout + 实际 availableWidth + expandedText`；输出横/竖算法、是否保留独立 section/heading 等最低信息。横向同排阈值应从两个 44pt 工具、间距与可见 chip 最小宽度派生；非法宽度或 `.xxxLarge`+ 回退堆叠，不用设备名/屏幕尺寸。
- 用一个 sessionList 和一个 actions 子树经 AnyLayout 复用；ForEach 按 session ID。0/1/多会话都保留动作与禁用原因，不以「只有一个」藏删除/导出。堆叠区承担当前标题/模拟摘要时不再重复 ChatWorkspaceHeading；split 聊天面仍有可发现的标题。
- hero 只有小型静态计算核心、语义标题/短说明、两张轻量 starter、真实模拟说明。starter 仍只 apply+focus、不自动 send；普通字号 iPhone 首屏优先让首个完整 starter 与 composer 可见，Accessibility 字号以完整滚动阅读优先，不缩字。
- ReadinessRing 在 shell 文件内改为主题 accent 同色系渐变，几何/百分比/辅助语义不变。surface owner 不并写此文件。
